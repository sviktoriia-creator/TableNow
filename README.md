# TableNow

Навчальний вебзастосунок для пошуку ресторанів і бронювання столиків.

## Стек
- Frontend: HTML5, CSS3, JavaScript (Fetch API)
- Backend: Node.js 22+, Express 5
- Database: SQLite (`node:sqlite`, вбудований експериментальний модуль Node.js; попередження ExperimentalWarning у терміналі очікуване)
- Захист: Helmet, хешування паролів через `scrypt`, HttpOnly session cookie, перевірка ролей, параметризовані SQL-запити

## Встановлення та запуск
1. Встановіть Node.js 22.16 або новішої версії (потрібен вбудований модуль `node:sqlite`).
2. У терміналі перейдіть до папки проєкту.
3. Виконайте `npm install`.
4. Створіть адміністратора (див. нижче).
5. Запустіть `npm run dev`.
6. Відкрийте `http://localhost:3000`.

## Створення адміністратора
Виконайте команду, підставивши власну адресу та складний пароль:

```bash
npm run create-admin -- admin@example.com "YourStrongPassword123!"
```

Не використовуйте наведений приклад пароля як реальний пароль. Пароль не зберігається у відкритому вигляді.

## Перевірка бази даних
Виконайте `npm test`, щоб запустити автоматизовані перевірки початкових даних, зв’язків таблиць, обмежень і зміни статусу бронювання.

## API
- `GET /api/health` — перевірка сервера.
- `POST /api/auth/register` — реєстрація.
- `POST /api/auth/login` — вхід.
- `POST /api/auth/logout` — вихід.
- `GET /api/auth/me` — поточний користувач.
- `GET /api/restaurants` — список ресторанів і фільтрація.
- `GET /api/restaurants/:id` — один ресторан.
- `POST /api/restaurants` — створення (адміністратор).
- `PUT /api/restaurants/:id` — редагування (адміністратор).
- `DELETE /api/restaurants/:id` — видалення (адміністратор).
- `GET /api/bookings` — список бронювань поточного користувача; адміністратор бачить усі.
- `POST /api/bookings` — створення бронювання.
- `PUT /api/bookings/:id` — редагування бронювання власником або адміністратором.
- `DELETE /api/bookings/:id` — скасування бронювання власником або адміністратором.

## Модель даних
- `users` — користувачі та ролі `user` / `admin`.
- `sessions` — хеші токенів сесій та термін дії.
- `restaurants` — ресторани, тип кухні, район, ціна та опис.
- `bookings` — бронювання, користувач, ресторан, дата, час, кількість гостей і статус.

SQLite-файл створюється автоматично: `data/tablenow.sqlite`.

## Межі навчального прототипу
Застосунок зберігає запити на бронювання, але не інтегрований із реальною системою ресторану та не перевіряє фізичну наявність столиків. Для публічного використання потрібні HTTPS, резервне копіювання, централізоване обмеження запитів, політика приватності та перевірка конфігурації розгортання.
